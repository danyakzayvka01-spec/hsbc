# HSBC Demo Portal — инструкция по настройке Firebase

В этой папке находятся публичная страница, вход, клиентский кабинет и отдельная панель администратора. Firebase Authentication отвечает за вход, Firestore хранит профили, демонстрационные балансы и PDF-документы, а Cloud Functions выполняют административные действия.

Это прототип для тестирования. Он не связан с банковскими системами HSBC и не перемещает реальные деньги.

## 1. Создайте проект Firebase

1. Откройте [Firebase Console](https://console.firebase.google.com/) и создайте проект или выберите существующий.
2. В обзоре проекта добавьте веб-приложение (значок **Web** `</>`).
3. В настройках приложения найдите блок конфигурации Firebase Web app. Значения понадобятся на шаге 3 ниже.
4. В разделе **Authentication → Sign-in method** включите способ входа **Email/Password**.
5. Создайте базу данных в разделе **Firestore Database**.

Официальная инструкция Firebase: [добавление Firebase в веб-приложение](https://firebase.google.com/docs/web/setup).

## 2. Подготовьте инструменты Firebase

Установите [Node.js](https://nodejs.org/) и Firebase CLI. Откройте терминал в папке `hsbc-firebase` и выполните:

```powershell
npm install -g firebase-tools
firebase login
firebase use --add
```

В последней команде выберите созданный проект. Если Firebase CLI спросит псевдоним, например `default`, подтвердите его.

## 3. Вставьте конфигурацию веб-приложения

Откройте файл `firebase-config.js` и замените значения `REPLACE_...` данными из настроек веб-приложения Firebase:

```js
export const firebaseConfig = {
  apiKey: "ваш-apiKey",
  authDomain: "ваш-проект.firebaseapp.com",
  projectId: "ваш-projectId",
  appId: "ваш-appId"
};
```

Эта веб-конфигурация используется браузером и не является приватным ключом сервисного аккаунта. Для публичного GitHub-репозитория ограничьте Firebase API key по HTTP referrer своим доменом и включите только необходимые API. Не публикуйте приватные ключи или пароли.

## 4. Установите функции и опубликуйте приложение

Cloud Functions могут потребовать платёжный план Firebase, поддерживающий этот сервис. Команды из папки `hsbc-firebase`:

```powershell
cd functions
npm install
cd ..
firebase deploy --only firestore:rules,functions,hosting
```

После публикации Firebase CLI покажет адрес сайта. Откройте его в браузере.

## 5. Создайте первого администратора

Назначить администратора можно в Firebase Console, без терминала. На сайте нет формы, которая позволяет пользователю самостоятельно повысить свои права.

1. В Firebase Console откройте **Authentication → Users → Add user** и создайте пользователя администратора с электронной почтой и паролем.
2. Скопируйте его **UID** из списка пользователей Authentication.
3. Откройте **Firestore Database → Data**. Нажмите **Start collection** и введите ID коллекции `admins`.
4. В поле **Document ID** вставьте UID администратора из шага 2.
5. Добавьте поле `enabled` типа **boolean** со значением `true` и сохраните документ.
6. Войдите в портал с электронной почтой и паролем этого пользователя. После проверки записи `admins/{UID}` откроется Account Studio.

Документ администратора добавляется вручную в Firebase Console, потому что консоль работает с административными правами. Правила Firestore запрещают создавать и менять документы `admins` из веб-приложения. Серверные функции перед каждой административной операцией также проверяют `admins/{UID}`.

### Если после входа появляется «нет необходимых разрешений»

1. В **Authentication → Users** откройте пользователя администратора и скопируйте его UID.
2. В **Firestore Database → Rules** опубликуйте правила из файла `firestore.rules` (скопируйте файл целиком в редактор правил и нажмите **Publish**).
3. В **Firestore Database → Data** проверьте, что существует документ `admins/{UID}` с полем `enabled` типа **boolean** и значением `true`.
4. Выйдите из портала и войдите снова.

Если правила уже опубликованы и UID-документ включён, откройте **Functions & Logs** и убедитесь, что `adminListClients` развёрнута: без этой Cloud Function вход администратора может пройти, но список клиентов не загрузится.

## 6. Вход и работа с аккаунтами

- Администратор и клиент входят на одной странице по электронной почте и паролю.
- Пользователь с ролью администратора попадает в **Account Studio**. Там можно создать тестовый аккаунт клиента, задать начальный баланс и валюту, указать полный вымышленный номер тестовой карты, изменить демонстрационный баланс и добавить клиенту PDF-документы.
- Созданный клиент входит со временным паролем, заданным при создании. Ссылка **Forgot your password?** отправляет письмо для сброса пароля, если адрес зарегистрирован.
- Для назначения валюты доступны USD, EUR и GBP. Это только обозначение валюты баланса: конвертации и курсы обмена не выполняются.
- Клиент открывает **Documents**, чтобы увидеть список прикреплённых к его профилю PDF и скачать их.

## Безопасность и ограничения прототипа

- Роль администратора определяется защищённым документом `admins/{uid}` с `enabled: true`. Callable Cloud Functions проверяют его на сервере перед административными действиями.
- Клиент не может записывать профиль и баланс напрямую в Firestore. Правила базы разрешают пользователю читать только собственный профиль; административные изменения выполняются Cloud Functions.
- Профили хранятся по адресу `users/{uid}`. Записи об изменении тестового баланса хранятся в `audit/{uid}/entries/{entryId}`.
- Для прототипа сохраняется полный вымышленный номер тестовой карты. Используйте только синтетический номер; не вводите реальные карты, CVV/CVC, PIN или срок действия. Карта не подключена к платёжной системе.
- PDF размером до 512 КБ сохраняются как Base64 в отдельном документе Firestore. Firestore ограничивает один документ размером 1 МиБ, поэтому лимит файла ниже этого значения с запасом на кодирование и метаданные ([официальные лимиты Firestore](https://firebase.google.com/docs/firestore/quotas)).
- Загружайте только вымышленные демонстрационные PDF. Не загружайте реальные выписки, документы личности, платёжные документы или сведения настоящих клиентов.
- Пароли обрабатываются Firebase Authentication и не записываются в Firestore.
- Список операций в кабинете пока состоит из примеров интерфейса. Переводы имитируются только в браузере и не сохраняются в Firebase.

## Файлы проекта

- `index.html` — публичная страница, форма входа, клиентский кабинет и панель администратора.
- `firebase-config.js` — конфигурация веб-приложения Firebase.
- `firebase-app.js` — вход, проверка роли, загрузка профиля и вызовы Cloud Functions.
- `firestore.rules` — правила доступа Firestore для профилей и документов.
- `functions/index.js` — серверные функции создания аккаунтов, списка клиентов, изменения демонстрационного баланса и доступа к документам.
