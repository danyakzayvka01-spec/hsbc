# HSBC branded banking simulation

Этот проект — визуальная симуляция личного кабинета. Он не является сервисом HSBC, не обрабатывает платежи и не должен использоваться с реальными личными данными. На страницах клиента и администратора остаются заметные предупреждения об этом.

## Настройка Firebase без Cloud Functions

1. В Firebase Console включите **Authentication → Email/Password** и создайте базу **Firestore Database**.
2. Проверьте конфигурацию веб-приложения в `firebase-config.js`.
3. Откройте **Firestore Database → Rules**, скопируйте туда `firestore.rules` и нажмите **Publish**. Правила для проекта `hsbc-27267` уже опубликованы.
4. В **Authentication → Users** создайте администратора. Скопируйте его UID.
5. В **Firestore Database → Data** создайте коллекцию `admins`, документ с ID равным UID администратора и поле `enabled` типа Boolean со значением `true`.
6. Загрузите папку проекта в подключённый к Vercel репозиторий или создайте новый deployment из неё.

Для создания аккаунтов, профилей и записей о транзакциях используются Firebase Authentication и Firestore. Firebase Cloud Functions и Cloud Storage не нужны.

## Работа кабинета

- Администратор создаёт отдельный аккаунт клиента с электронной почтой и паролем, задаёт один баланс, валюту, вымышленный номер карты, ФИО и профильные сведения.
- Клиент входит под назначенными логином и паролем. В кабинете показываются его баланс, карта, недавние записи и сведения из **Profile Settings**.
- При создании аккаунта список транзакций пустой. Администратор может добавить тестовый расход или доход, указать контрагента, описание, сумму, дату и статус.
- Добавление записи в историю не меняет баланс аккаунта.
- Кнопка перевода показывает предложение связаться с менеджером. Переводы не выполняются.
- Профили хранятся в `users/{uid}`, а записи транзакций — в `users/{uid}/transactions/{transactionId}`.

## Ограничение создания аккаунтов без сервера

Форма проверяет активную админскую запись, а правила Firestore ограничивают создание и просмотр профилей администраторами и владельцами аккаунтов. Однако Firebase Authentication не предоставляет правила Firestore для запрета прямой регистрации посторонним. Без доверенного серверного API технически возможно создать отдельную Auth-запись без профиля. Эта запись не получает доступа к данным клиентов.

## Файлы

- `index.html` — публичная страница, кабинет клиента и панель администратора.
- `firebase-app.js` — логин, создание аккаунтов, загрузка профилей и истории транзакций.
- `firebase-config.js` — конфигурация веб-приложения Firebase.
- `firestore.rules` — доступ к административным записям, профилям и транзакциям.
- `vercel.json` — заголовки безопасности для сайта.
